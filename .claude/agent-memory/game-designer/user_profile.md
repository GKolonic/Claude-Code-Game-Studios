The user is an indie game developer building The Faithful as a solo project. They have a clear design vision and are authoring GDDs themselves. They ask for specific, numbered, implementable rules — not vague design theory.

**Collaboration style preferences observed:**
- Prefers unambiguous numbered specifications over prose descriptions
- Asks targeted, structured questions before drafting ("what triggers X? can Y move backwards?")
- Is comfortable with game design terminology (belief state, cooldown, schema, enum)
- Designs incrementally — one GDD section at a time, seeks approval before writing
